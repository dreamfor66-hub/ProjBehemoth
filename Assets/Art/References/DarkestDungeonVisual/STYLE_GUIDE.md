# DD 분위기와 실제 방 색의 필수 기준 — 2026-11-01

## 기준의 역할

1. 사용자 최신 지시·승인·보존 범위가 우선이다. 승인된 플레이어 얼굴·정체성·장비·포즈·크기·Sprite geometry를 분위기 교정 명목으로 다시 디자인하지 않는다.
2. 이 폴더 `Images/01–07`의 **실제 DD 화면**은 게임 전반의 모험 분위기·명암 위계·조명·먹면에 대한 최신 시각 기준이다. `Darkest Dungeon`이라는 이름만 프롬프트에 적는 것으로 대체하지 않는다.
3. `ProjectContext/B1-01-Original.png`는 B1의 승인된 카메라·소실점·바닥 높이·벽 지지면과 기존 재료 색 기준이다. 막2/3와 방 변주도 이 바닥 투시 기준을 잇는다. 기둥·장식·방의 목적은 달라도 된다.
4. `B1-02/03`은 사용자가 허용한 팔레트 변주, `B1-04/05`는 거부한 색 이탈 사례다. 거부본을 다음 생성의 유일한 스타일 기준으로 쓰지 않는다. AngularCharacter/Monster 원본은 형태·선·정체성 비교에 병행한다.

## 실제 참고에서 가져올 것

- **어두운 바탕과 읽히는 활동 영역.** 방 전체를 균일하게 밝히지 않는다. 얼굴·손·무기·상호작용 대상은 큰 어둠 속에서 읽히며, 구석과 배경 장식은 시선을 덜 끈다. 중요 대상을 작은 크기나 어두움만으로 숨기지 않는다.
- **이유 있는 제한된 빛.** `01/03/06`의 차가운 돌과 작은 불빛, `02`의 주황 균계, `07`의 붉은 하늘은 서로 색이 다르지만 광원과 장소가 설명한다. 모든 방을 동일 RGB로 만드는 규칙이 아니다. 빛이 없는 돌 전체가 이유 없이 황금색·카키색으로 바뀌는 것은 실패다. 따뜻한 횃불이 있다고 모든 그림자·바닥·소품에 같은 노란 막을 씌우지 않는다.
- **실루엣 안쪽의 큰 먹면.** 두꺼운 외곽 테두리만으로 통과시키지 않는다. 얼굴의 눈구멍, 옷의 깊은 가림, 사물 밑면, 벽 틈에 넓고 단단한 검은 형태가 들어가며 중요한 형태와 대비를 만든다. 균일한 벡터 테두리·글로우·외곽 후광으로 읽힘을 해결하지 않는다.
- **닳고 위험한 큰 형태.** 무게·기울기·낡은 비대칭·지친 얼굴이 모험의 흔적을 만든다. 'clean large forms'는 갓 찍은 매끈한 공장 블록·완구·아이콘처럼 만들라는 뜻이 아니다. 반대로 낡음을 잔균열·돌 조각·털 한 올·점 노이즈로 빽빽하게 채우지 않는다. 거친 선택적 선과 소수의 큰 마모 면으로 정리한다.
- **장면 위계.** 배경·NPC·상자·분수·문은 같은 세계의 재질과 조명을 공유한다. 상호작용 가능하다는 이유로 사물만 더 밝고 선명하고 촘촘하게 그려 버튼처럼 만들지 않는다. 큰 색 덩어리와 실루엣은 읽히되 어두운 주변과 접촉한다.

## 생성 전에 반드시 볼 입력

관련 DD 원본 최소2장(해당 장면의 광원·재료에 맞춰 선택), 실제 승인된 막 기본 배경, 변경할 방/문/사물의 실제 생산 PNG, 합성된 기존 게임 화면을 직접 연다. 승인된 배우가 함께 등장한다면 그 배우의 실제 그림도 붙인다. 각 입력의 역할을 `mood authority / approved geometry+palette / target / identity`로 기록한다. 다른 생성본만 계속 재참조해 스타일과 색을 재정의하지 않는다.

PNG에 조명이 이미 그려졌는지, 런타임에서 어떤 tint가 적용되는지 확인한다. 사전에 색이 입혀진 재료에 같은 색 tint를 다시 곱하는 이중 착색을 금지한다. 하나의 근본 원인이면 원본 입력 또는 공통 적용 규칙에서 해결한다. 방마다 수작업 보정값을 복제해 어긋남을 숨기지 않는다.

투명 문 오버레이는 개구부·문틀·실제 문턱만 포함해야 한다. 원래 배경에서 잘라 온 기둥/벽/바닥 조각이 사각형으로 남으면 기본 방에서는 감춰져도 다른 방에서 색 패치가 된다. 최소 두 종류의 방에 합성해 알파 경계와 주변 건축의 이어짐을 확인한다. 원화 편집 결과가 문 좌표/형태를 바꿨으면 색이 좋아도 반려한다.

## 합성 화면 검수의 통과 조건

각 수정은 아래 근거를 저장하기 전까지 **미검수**다. 고립 PNG나 생성 프롬프트, 컴파일, '더 어둡다'라는 말만으로 통과시키지 않는다.

1. **기본 방 / 변주 방 / 문 포함 / 사물 포함**을 실제 같은 표시 크기에서 나란히 본다. 도어 오버레이·문틀·플레이어·사물을 모두 포함한 전체 화면이어야 한다. 관련 막1/2/3와 앞/측면을 비교하고, 실제 다시 보게 되는 후면·사용 후 상태도 확인한다. 목적별 방이 있어도 기본 카메라와 바닥 높이가 바뀌지 않는다.
2. **같은 재료를 직접 비교하고 수치도 기록한다.** 주변 석재, 문틀 석재, 바닥, 사물의 공통 재료에서 광원 조건이 비슷한 작은 면을 선택한다. 이미지/상태/좌표, 대표 RGB, linear-sRGB 상대 명도 Y와 기준 대비 차이를 적는다. 불꽃·UI·선·강한 반사면을 재료 기본색으로 샘플링하지 않는다. 샘플이 다른 음영 면이거나 카메라가 다르면 그 한계도 적는다. 수치만으로 합격시키는 보편 임계값은 만들지 않는다.
3. **접합선을 본다.** 문틀과 벽, 벽 오브젝트와 벽, 기단과 바닥의 경계에서 색온도·명도·먹선 두께·마모 밀도가 갑자기 끊기면 실패다. 문/배경 둘 다 각각 그럴듯해도 합성에서 회색 문틀만 떠 보이면 고친다. 충분히 큰 전체 화면과 원래 화면 크기를 모두 보며, 축소로 접합을 숨기지 않는다.
4. **조명 변화의 이유를 설명할 수 있어야 한다.** 광원 가까운 면이 따뜻하고 그 반대 그림자가 기존 재료를 유지하는지, 새 장소라면 장소의 광원이 화면에 드러나는지 본다. 방 종류가 바뀌었다는 데이터 이름만으로 전체 황색 이탈을 정당화하지 않는다. 서로 다른 빛의 방이 모두 동일색이어야 하는 것은 아니다.
5. **투시·접지·상태 연속성.** 바닥선·기둥·발·상자 하부·분수 기단이 같은 바닥에 놓이는지 확인한다. normal/used는 같은 고정 캔버스·지지점·표시 스케일을 사용하고 실제 그림 속 고정 몸통도 이어져야 한다. `fullFrame` 불변 검사는 독립 원화 내부의 몸통 모서리까지 같다는 증명이 아니다. 변환·비균등 스케일로 다른 투시의 원화를 억지로 맞추지 않는다.
   동료는 플레이어와 같은 카메라를 공유한다. 탐험과 전투의 확대/하강을 모두 비교하며, 전신을 작은 크기로 넣거나 화면 하단 지지점을 고정한 채 확대만 해 거대해 보이는 구도를 금지한다. 허용된 하단 잘림은 실제 가까운 구도에서 판단하고, 투명한 배우 캔버스가 보이는 동료의 클릭을 막지 않는지도 확인한다.
6. **노출과 재질을 함께 판단한다.** 단순 어둡게 만들기, 갈색 필터, 검은 비네트, 대비 증폭만으로 DD 일치라고 쓰지 않는다. 큰 먹면·읽힘 위계·거친 선택적 선·절제된 재료·장면 이유가 함께 있어야 한다. 보호된 플레이어 얼굴이나 승인 포즈를 건드려 배경 실패를 보상하지 않는다.

불일치를 발견하면 이미 승인된 작업 범위 안에서 수정→새 합성→재검수를 반복한다. 읽기 전용 검수나 명시적인 소유 범위 제한을 받은 경우에는 해당 담당자에게 구체적인 화면/재료/경계를 즉시 전달하고 미검/실패로 남긴다. 검수자, 실제 파일명·해시/시각, 발견과 교정 결과, 남은 한계를 생산 기록에 남긴다. 과거 실패 캡처를 교정 후 최종 상태로 재사용하지 않는다.
