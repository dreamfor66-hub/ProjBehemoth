# 중앙 UI 및 고정 상점

## 반영 범위

- 보상·퍽·상점·소이벤트·사건·종료 창은 MainGameScene의 `Canvas/CenterModalLayer` 안에서 표시된다. 중앙 영역은 510 × 820이며, 전투/스펠 HUD보다 뒤에 추가된 최상위 형제 계층이다. 표시하는 팝업만 이 계층 안에서 맨 앞으로 올린다.
- OutGameScene은 동일 크기의 `Canvas/SelectionCenter`에 제목 → 3열 2행 캐릭터 선택 → 캐릭터 설명/능력치/시작 유물 → 시작 버튼 → 조작 안내를 배치한다.
- 기존 전투 캐릭터의 HP/가드는 그대로 둔다. 좌측 하단 `LeftPanel/CharacterSummary`에 초상화, 이름, 현재/최대 HP, 레벨/EXP 게이지, 소지 골드를 추가했다. 기존 중복 층/EXP/골드 텍스트는 숨기고 층 이름은 상단에만 남겼다. 피해/회복/성장 수치는 실시간 갱신한다.
- 긴 사건 본문·시작 유물·상점 상품 설명은 스크롤로 끝까지 읽는다. 그림이 없는 사건은 그림 공간을 본문에 사용한다.

## 상점 규칙

- 상인마다 처음 생성된 상품을 고정한다. 다른 상인의 상품까지 전역 공통 목록으로 고정하는 의미는 아니다.
- RunController의 `Shop Stock Size`로 5~6개를 설정한다. 저장된 기본값은 6개다. 기존 장비/포션 데이터와 해금 조건에서 생성하며 구매·성장·화면 재표시 때문에 상품을 다시 추첨하지 않는다.
- 같은 실행의 seed/act/room 조합은 동일한 목록·순서·객체를 반환하며, 새 탐험 시작 시 초기화한다. 기존 maxPurchaseCount 제한은 유지한다.
- 구매 불가 상품도 슬롯을 유지하고 품절/보유 중/습득한 주문/포션 슬롯 부족/골드 부족을 표시한다. 살 수 있는 상품이 없어도 자동 퇴장하지 않는다.
- 주문 교체를 취소하면 골드를 소모하지 않으며 수락 후 구매가 성공해야 새 주문을 배운다.

## 저장 및 검증

- `BehemothUiPreparation`은 스키마 21까지 한 번만 편집기에서 준비하여 두 씬에 저장한다. 이후 디자이너 배치를 자동 재생성하지 않는다. 저장되지 않은 씬이 있으면 준비를 보류한다. 별도 메뉴 조작은 필요 없다.
- 이번 변경 전용 `ui-tests`는 UI/상점 테스트만 실행한다. 전체 DPS·전투 회귀 검사는 포함하지 않는다.
- 결과: `Logs/Behemoth-TestResults.xml`, `Logs/Behemoth-PlaytestMatrix.txt`, `Logs/Behemoth-UI-*.png`.
- 변경 범위 전용 5개 테스트 통과: 고정 재고/새 탐험 초기화, 중앙 영역 및 계층, 6종 선택, HUD 실시간 수치, 보상 입력 차단, 사건 스크롤/페이지, 구매·품절·포션 슬롯 부족·주문 교체 취소/수락·퇴장. 전체 DPS 테스트는 실행하지 않았다.
- 로컬 실제 마우스로 로그 선택 → 긴 시작 유물 설명 스크롤 → 탐험 시작 → 중앙 안내 확인 → 탐색 복귀까지 확인 후 Play 모드를 종료했다.
- 실제 기기 터치 및 세로 해상도 대응은 이번 변경의 검증 범위에 포함하지 않았다.
