# 로케일 검색·편집

Unity 메뉴 **Behemoth > 텍스트 > 로케일 검색·편집**에서 연다.
LocalizedData 또는 한국어 테이블 Inspector의 같은 이름 버튼으로도 열 수 있다.

1. 화면에 보이는 문구의 일부를 검색한다. 키·한국어 원문·출처를 검색하며 개행과 연속 공백을 같은 공백으로 취급한다.
2. 결과를 선택해 안정적인 키와 원문을 확인한다. 예: `야영은 이 층` → `ui.camp.intro`.
3. 한국어 문구를 편집하고 **저장 · 테이블 / 데이터 / CSV**를 누른다. Play 중에는 검색할 수 있고 영구 저장은 Play 종료 후에 한다.
4. **이 키의 사용처 찾기**를 누르면 코드·데이터·씬·프리팹의 직접 참조를 확인할 수 있다. 결과를 누르면 코드 줄을 열거나 해당 에셋을 선택한다. 동적으로 조합하는 키는 직접 참조 검색에 나오지 않을 수 있다.

## 유지할 규칙

- 문구를 바꿔도 기존 키는 유지한다. 데이터의 자동 생성 키와 `textKeys` 바인딩을 임의로 재생성하지 않는다.
- `{0}`, `{1}` 등의 인자 번호는 보존한다. 순서와 숫자 출력 형식은 수정할 수 있다. 일반 중괄호는 `{{`, `}}`로 입력한다.
- 저장은 한국어 테이블과 해당 키에 연결된 LocalizedData 필드를 함께 갱신한다. CSV는 선택한 행만 바꿔 다른 행의 외부 편집을 보존한다.
- 같은 키의 테이블·연결 데이터·CSV가 편집 시작 값과 다르면 저장을 중단하고 충돌을 알린다. 외부 CSV를 기준으로 편집하려면 기존 **한국어 CSV 가져오기**를 사용한 뒤 현재 값을 다시 읽는다.
- 게임 내 기존 UI 바인딩은 갱신하며, 동적으로 만든 모달 문구 등은 다음에 화면을 표시할 때 적용한다.

## 요구사항 및 검증 기록 — 2026-10-25

- [x] 보이는 문구로 검색하고 키·원문을 함께 표시
- [x] 같은 창에서 직접 편집·저장
- [x] 실제 사용처 및 원본 에셋으로 이동
- [x] 안정적인 키·한국어 CSV·데이터 동기화 유지
- [x] 빈 검색 결과, 수정 상태, 미저장 이동·닫기 안내, 저장 성공·실패, 치환자 오류, 외부 수정 충돌 처리
- [x] 기존 Unity Editor에서 컴파일 및 검색 창·결과 선택·사용처 버튼 확인
- [x] 범위를 제한한 저장 검증 18개 통과: 문구/키/없는 결과 검색, 치환자 순서·서식·누락·잘못된 괄호·이스케이프, CSV 쉼표·따옴표·개행, 다른 행 보존, 동일 행 충돌, 실제 코드 참조, UI 키와 데이터 키의 저장·복구
- [x] 검증 후 테이블 파일의 SHA-256이 검증 전과 일치함을 확인. CSV도 원문과 원래 행 형식으로 복구함.

검증 도구는 명시적으로 `Temp/BehemothLocale.request`에 `verify`가 들어온 경우에만 기존 Editor에서 실행한다. 결과는 `Logs/Behemoth-LocaleVerification.txt`에 기록한다. 게임의 물리·입력 동작은 변경하지 않았다.

검증 중 Play 종료 시 기존 TypographyPreparation.Prepare의 씬 열기 예외가 관찰되었다. 로케일 검증 18건은 통과했으며, 이 작업에서는 별도 진행 중인 타이포그래피 코드를 변경하지 않았다.
