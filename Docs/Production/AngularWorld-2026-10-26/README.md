# Angular world 적용 결과

> 2026-10-26 후속 정정: 아래의 빠른/느린 교대 일반 공격 8종은 사용자 요청에 따라 제거하고 원래 일반 공격 준비 시간으로 복원했다. 현재 효과와 등급/동행 관계의 전체 목록은 ../MonsterComparison-2026-10-26/Gallery.html 기준이다.

기존 선택 UX를 유지해 `SelectionPage`로 이름을 통일하고 승인된 6종을 상반신 중심으로 확대했다. 버튼·상세·뒤로·시작의 기존 연결을 유지했다. 선택 씬의 모든 RectTransform은 작업 전 백업과 개행 정규화 후 동일하다. TMP 크기 값의 저장 차이는 기존 TypographyRoleBinding의 실행/직렬화 결과다.

몬스터 41종(3층 실제 출현 37 + 특수/시련 4), 전투용 뒷모습 6종(승인 워리어 재사용 + 5종 제작), 얼굴을 다시 그리지 않은 HUD 크롭 6종, B1/B2/B3 배경을 적용했다. 이벤트 3:4 삽화와 주술자는 후속 요청으로 남겨 두었다.

- [원본/신규 콘셉트 및 공격 대응](Roster.json), [생성 프롬프트](PromptSet.json), [스타일 검토와 실제 수정](StyleReview.md), [최종 파일 해시/크기](Outputs.json).

## 기획과 구현

박쥐의 층별 색상 변형 대신 도깨비·전갈·실망령·사슴·나방·일각수·뱀수문장·흡혈귀·용 등 다른 실루엣을 사용했다. 기존 거울 반격·3연타·공전·소환·연결 보조 개체를 새 콘셉트와 안내에 맞췄다. 8종에는 데이터 목록으로 빠른 견제/느린 후속 공격을 번갈아 사용하는 일반 공격을 추가했다. 준비 시간은 기존의 0.6/1.4배로 평균을 유지하고 타격 수/개별 피해량은 보존했다. 기존 공격 에셋을 직접 덮지 않고 복제한다.

배경은 각 층의 벽 바탕 + 정면/좌/우의 투명 출입구 레이어다. 현재 방의 실제 연결과 바라보는 방향을 매 프레임 확인한다. 이웃 방이 존재해도 연결되지 않으면 벽이다. 잠긴 문 규칙은 사용자가 설명할 후속 범위여서 구현하지 않았다.

새 적의 체력·주기·스턴·보상·지원 개체·공전 등 533개 기준값을 기존 데이터와 비교해 동일함을 확인했다([Pacing-Invariants.json](Pacing-Invariants.json)). 이는 전체 체감 밸런스 검증을 대체하지 않는다. 지상형 표시 중심은 발이 바닥에 닿도록 조정했으며, 타격 중심과 약점 중심도 함께 이동한다.

## 범위를 한정한 Unity 실행 검증

| 대상 | 검증 방법 | 결과/기록 |
|---|---|---|
| 선택 6종 | 저장된 OutGameScene, 기존 버튼 클릭, 확대 그림/상세/뒤로/재진입 | `Live.txt`, Selection 스크린샷 |
| 몬스터 41종 | 저장된 MainGameScene에서 각 데이터의 실제 그림/이름, 강타 약점 표시 | 통과, Monster/Ready 스크린샷 |
| 출입구 | 4방향 × 8연결 조합, 연결되지 않은 이웃 방 포함 | 32조합 통과 |
| 3층 배경 | 각 층 벽/3문/정면+우측 | 통과, B1/B2/B3 스크린샷 |
| 순차 일반 공격 8종 | Play mode MonsterRuntime 4행동씩, 순서/종료/피해량 | 통과 |
| 실제 컨트롤러 | 전갈의 빠른/느린 2행동과 재순환 | 통과 |
| 캐릭터 6종 | 실제 입력 처리기의 스와이프 타격, 드래그 유지 방어, 상태 그림 | 최종 재검증 통과 |
| 옮긴 적 중심 | 스와이프 타격, 강타 약점 표시 | 통과 |

최초 방어 검증은 입력 유지 없이 런타임 플래그만 켜서 입력 처리기가 다음 프레임 해제하는 문제로 실패했다. 테스트를 실제 Begin/Move/End 드래그 유지로 수정한 마지막 VISUAL 실행에서 6종 모두 통과했다. 과거 실패 로그도 `Live.txt`에 보존했다. 실제 장치 터치/전체 DPS·밸런스 회귀는 실행하지 않았다. 한 개의 기존 Unity Editor에서 변경된 아트·입력·패턴만 확인했다.

생성 모드: 내장 `image_gen`, 투명 배경. 41종/층별 배경/5종 뒷모습은 제공 레퍼런스를 입력한 생성, 스타일 수정 3건은 편집. 선택과 HUD는 승인된 정면 원본의 크롭이고 워리어 뒷모습은 기존 승인 그림 재사용이다. 원본과 최종 자산을 프로젝트에 분리 저장했다.
