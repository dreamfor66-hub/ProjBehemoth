# 정규 상태 이미지 연결 · 최종 검증

2026-10-27 재점검: 위의 완료 범위에서 훈련 인형 TrainingLight/Medium/Heavy 3종이 제외되어 있었다. 이 3종은 기존 픽셀 4개 상태 연결은 정상이나 2D 전환은 미완료다. 전체 범위의 누락 여부는 CompletenessCheck.md / CompletenessCheck.json을 함께 참조한다.

- 6 캐릭터: 후면 Idle / Attack / Guard, 각 상태 대표 이미지 한 장.
- 41 몬스터: Idle / Ready / Attack / Dead, 각 상태 대표 이미지 한 장.
- 동행견: 후면 Idle / Attack. Guard 없음.
- 총 48개 개체, 184개 상태 이미지. 새 이미지 137장: 캐릭터 12, 몬스터 123, 동행견 2.
- 원래 승인된 캐릭터·몬스터 Idle 47개 파일의 SHA256 보존. 동행견의 기존 픽셀 전투 이미지는 2D로 교체, 기존 원본은 보존.
- 모든 데이터는 Inspector에서 확인 가능. 별도 메뉴 조립 필요 없음.
- Idle을 다른 상태에 복제하거나 회전/확대로 포즈를 대신하던 설정 해제.

|범위|실제 Unity 실행 검증|
|---|---|
|캐릭터 6종|공격 수락→Attack, 쿨다운 거절 시 포즈 재시작 없음, Idle 복귀, 실제 드래그 홀드→Guard, 해제→Idle|
|위자드|수락된 주문도 Attack 전환|
|공격 몬스터 39종|실제 일반 공격 준비→Ready, 타격→Attack, 치명 피해→Dead|
|공격하지 않는 해/달 우상 2종|4종 상태 슬롯과 고유 이미지 확인, 실제 Dead 전환. 비공격 설계 유지|
|동행견|Idle 및 자율 Attack 전환. 플레이어 Guard 중에도 독립 전환|

모든 최신 설치 해시가 Verified 기록과 일치한다. Audit.json에서 48개 전부 통과.
캐릭터/몬스터/동행견 데이터의 공격 간격·패턴·수치 및 기존 canvasScale/combatPositionOffset/labelHeight 설정 보존을 백업과 대조했다. 기존 데이터에서 생략된 값은 ScriptableObject 기본값으로 비교했다.

실인형·폭풍 해파리는 검증용 단일 적 설정이 승리 코루틴을 먼저 예약하는 문제를 수정했다. 실제 동행 그룹으로 바꿀 때 이전 검증용 전투를 종료하도록 검증기만 수정했으며, 게임 동행/전투 규칙은 바꾸지 않았다. 초기 실패 로그는 이력을 위해 보존했다.

검증은 기존 Unity Editor 한 인스턴스에서 변경 범위만 실행했다. DPS/전체 회귀/실기기 균형 검증은 실행하지 않았다.

이미지 제작: 내장 image_gen. 최종 PNG는 Assets/Art/World/Angular/States/, 프롬프트는 FinalPromptSet.json에 저장했다.

후속 수정: 완료된 승인 기록을 PNG 해시 검사보다 먼저 확인하도록 자동 적용기를 수정했다. 기존에는 설치 완료 후에도 3초마다 184개 이미지(약 191 MiB)를 다시 읽었다. 이제 승인 내용이 바뀐 세트만 이미지 검증·적용하며, 48개 세트의 기존 검증 결과와 아트/게임 데이터는 유지된다. 이 반복이 Codex 명령 정체의 직접 원인인지는 확인되지 않았다.
