# 실제 지도 기반 피로도 예산

현재 생산용 생성기·실제 설정(YAML)을 그대로 참조하는 제한된 .NET 감사다. UnityEngine의 데이터 속성·수학·곡선은 최소 스텁이며, Unity 런타임/입력/곡선 보간 품질 검증은 별도다. 전투/DPS 검사는 실행하지 않았다.

지도마다 시작→모든 방→보스의 합법적인 유한 경로를 만든다. 보스 최단 경로를 마지막 축으로 남기고, 나머지는 실제 연결을 왕복한다. 루프의 지름길은 최적화하지 않는 보수적 탐험 경로다. 숨은 입구 발견 클릭은 이동이 아니며 이동비용이 없다. 잠긴 가지에서 열쇠를 아직 못 찾았으면 기본 지도를 탐색한 다음 실제 입구까지 되돌아오는 거리를 포함한다. 방의 내용을 알고 최단 이동하는 가정이나 무한 왕복을 버틸 가정은 하지 않는다.

`최대 피로도 = 10 × ceil(max(100, (전체 경로 이동 수 + 1) × 실제 이동 비용) / 10)`으로 정한다. 0이 사망이므로 마지막 방 도착 후 실제 한 걸음 비용을 남긴다. 캠프나 물약을 필수로 쓰지 않아도 정해진 한 차례 전체 탐색은 이동 때문에 막히지 않는 기준이다. 전투 성능 페널티는 기존 0–100 곡선에 잔량 비율을 대입한다. 캠프는 최대치, 짧은 휴식은 최대치의 기존60%, 회복 포션은 기존 실제30(비용2일 때15보)이다. 실제 캠프 한 번을 쓰는 경우도 함께 계산해 증가량을 숨기지 않았다. 반복 짧은 휴식/물약을 생존 계산에 더하지 않았다.
