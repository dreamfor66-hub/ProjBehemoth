# 실제 Native 프레임의 전투 화면 검수

저장된 MainGameScene의 기존 단일 Unity Editor에서 7종31자세와 위자드 네 자세를 별도로 확인했다. `CombatRuntimeReview.txt`는139항목/0실패다. 해당 화면은 `Screens/Final-Combat-*`, `Final-Player-Wizard-*`다. 전투 수치 비교나 별도 Editor의 전체 회귀를 실행하지 않았다.

## 검수 방법과 반려

첫 캡처는 Animator의 Sprite만 바꿔 Native Sprite 각 프레임의 crop rect/pivot을 실제 MonsterView.Bind에 반영하지 않았다. 이 방식으로 찍힌 `Combat-*`의 사망 접지를 합격 근거로 쓰지 않았다. 최종은 실제 MonsterRuntime의 StartCharge/BeginNormalAttack/EnterStun/TakeDamage와 생산용 MonsterView.Bind를 사용한다. 실제 약점 표시도 함께 갱신한다. 종별 scale은 유지되는지 매 자세 확인했다. 소환 실인형을 주인 없이 소환해 사라진 초기 픽스처도 반려했고, 실제 supportRoster의 주인과 함께 생성해 원래 무리의 크기와 위치를 사용했다.

Root는 고블린 사냥꾼·납골당의 종·철니 미믹의 원화 및 실제 Idle/Ready/Attack/Dead/Stunned(있는 경우), 위자드 탐험/네 전투 자세를 직접 열었다. 다른 독립 검수자가 실인형·종토끼·공허의 눈·숯불 도롱뇽17자세를 실제로 열었다. 독립 결과는 `../IndependentWorldArtReview.md`다.

## 실제 발견과 수정

- 고블린의 창·어깨·손, 납골당의 종의 종 껍질·손·추, 미믹의 입·팔은 큰 먹 면과 절제된 재질로 읽힌다. 직접 바인딩한 Native 사망 그림은 원래 바닥에 놓인다. 단순 Sprite 교체 캡처의 부유 인상을 생산 아트 결함으로 오인하지 않았다.
- 납골당의 종 Ready 왼쪽 약점이 들어 올린 손 아래 빈 공간에 있음을 최종 화면에서 발견했다. 활성 Native charge asset의 `lock_0.localPosition`을 `(-212.5,0)`에서 `(-172,126)`으로 옮겨 실제 손 위에 부착했다. 다른 두 점·반경29·필요1타·노출4.8초·피해/방패 피해·공격 간격은 그대로다. 이전 파일은 `../Before/NativePoseReview/`에 보존했다. 2/3막 튜닝과 약점은 바꾸지 않았다.
- 독립 검수의 다른 네 종 Ready에는 명백한 공중 약점이 없었다. 토끼/도롱뇽 사망 접지, 공허의 눈의 부유/추락 구분을 확인했다.
- 위자드의 후면·부엉이·지팡이·네 독립 자세는 실제 탐험/전투 크기에서 표시되며 빈 흰 사각형이나 잘못된 폴더의 그림을 사용하지 않는다. 전투 포즈를 절차적 회전·찌그러뜨리기로 만들지 않았다.

## 판정의 한계

실제 무리의 작은 실인형 Ready/Attack에서는 기술명 검은 띠가 상체 상당 부분을 가린다. 노출된 실루엣·기절·사망과 정확한 프레임 바인딩은 검수했지만, 두 포즈의 전체 그림이 실제 UI 아래에서 언제나 완전히 보인다고 주장하지 않는다. 기술명/무리 UI 배치 전체를 이번에 재설계한 것은 아니다. 독립 원화 비교판과 실제 화면의 검수 범위를 구분한다.

약점은 화면 부착 위치를 대조했다. 차지 입력·브레이크·DPS·모든 무리 조합의 성능 검증까지 실행했다고 확대하지 않는다. 자연스러운 다섯 판의 난이도/반복감 평가는 사용자 플레이 피드백으로 남긴다.
