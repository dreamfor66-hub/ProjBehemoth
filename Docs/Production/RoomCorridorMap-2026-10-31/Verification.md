# 검증 결과

- EditMode: `DungeonMapLayoutTests` 4개 통과, 실패 0. 상세 결과 `EditMode.xml`.
- 현재 사용자의 Unity Editor Play 모드: 21개 통과, 실패 0. 상세 결과 `Live.txt`.
- B1/B2/B3 각 5개 고정 시드: 방/이벤트 수, 연결성, B1 초반 전투와 분기 제한, 인접한 미연결 경로 금지, 2×2 밀집 금지 확인.
- 큰 방/작은 사건의 데이터 분류 및 실제 크기, 미탐험 공개 범위, 작은 셀의 44 클릭 영역과 EventSystem 실제 raycast 확인.
- 실제 DungeonController 이동 콜백의 목적지/방향, 먼 방 클릭 차단, 통로 장식 입력 비차단 확인.
- 실제 UI 드래그 핸들러의 이동/플레이어 위치 유지, 두 번째 접촉의 소유권 탈취 차단 및 원래 접촉의 지속 이동 확인.
- 확대/축소 범위, 저장된 내 위치/닫기/지도 열기 버튼 콜백, 이동 불가 상태의 선택 차단 확인.
- 최종 실제 게임 화면에서 방과 작은 셀의 크기 차이, 통로 간격, 현재 위치, 선택 강조, 한글 안내를 시각 검토. 야영지 표기를 두 글자 ‘야영’으로 수정해 줄바꿈 해소.

`01-Start-Fog.png`는 실제 초기 공개 상태, `02-Rooms-And-Corridors.png`와 `03-Overview.png`는 동일 생성 맵의 탐험 상태를 검증 코드로 공개한 배치 검토 화면이다. 후자의 전체 공개는 제품 동작 변경이 아니다. `Map-Preview.png`는 두 번째 게임 화면에서 지도 패널을 자른 미리보기다.

윈도우 마우스 입력 시도는 사용자의 동시 데스크톱 사용 중 안정적인 이동 증거를 얻지 못했으므로 통과로 계산하지 않았다. 입력 검증은 live Unity의 실제 EventSystem raycast와 제품 핸들러/이동 콜백으로 수행했다. 실기기 터치 조작과 장기 탐험 피로도/경로 밸런스 평가는 미검증이다. 전투/DPS/전체 회귀 또는 별도 Unity 인스턴스는 실행하지 않았다.

검사 종료 후 Play 모드를 종료한다. 디자이너 수정과 기존 staged 변경을 유지하며, 프로젝트를 열 때 저장된 지도 UI/데이터 참조가 준비된다.
