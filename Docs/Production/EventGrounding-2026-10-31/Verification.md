# 이벤트의 공간 일치 · 아트 검수 — 2026-10-31

1~3막에 적용했다. 전체 24개 사건의 서사를 검토했고, 기존 활성 19개에 각자 고유한 발견 대상과 선택 후 상태를 연결했다. 기존 제외 5개는 제외를 유지했다. 비용, 보상 효과, 조건, 페이지 분기, 등장 가중치와 막 범위는 원본과 동일하다.

## 플레이에 반영된 내용

- 보이지 않는 연구실·연금술실·강의실·우물방을 전제하는 시작을 길가의 인물, 동물, 휴대 가능한 물건으로 고쳤다. 과거 예약한 배달은 표식 붙은 꾸러미와 쪽지로 발견하며 없던 배달원이 나타나지 않는다.
- 인물의 대화 종료, 실제 떠남, 사물의 소진/잔존과 재클릭 문장을 선택별로 연결했다. 떠나는 인물은 제거하고, 남는 인물은 상황에 맞는 짧은 반응을 한다. 열매, 금고, 배달품, 훈련 인형은 선택에 맞는 소진 그림을 사용한다.
- 활성 사건의 최초 그림은 19개 모두 다르다. 상점, 일반 상자, 비밀 입구의 단서 그림과도 공유하지 않는다. 이벤트 그림이 없을 때 공용 수상한 상자로 대신하는 경로를 없앴다.
- 상인은 부드러운 후드에 얼굴 대부분이 가려진 인물로 교체했다. 동일한 인물의 후속 마법 수업도 두루마리/펼친 책/수정 지팡이의 별도 그림을 사용한다.
- 사람과 동물은 실제 첫 진입 방향을 기준으로 얼굴이 보이는 먼 쪽 바닥에 배치한다. 처음 한 번 정한 세계 방향과 모서리는 재방문에 보존한다. 그림의 실제 크기와 이동 버튼 영역을 비교하여 가림이 덜한 바닥 자리를 고른다.
- 같은 계열의 상인/여신상/분수는 같은 층에서 최단 이동 거리 4칸 이상을 확보한다. 독 분수는 분수 계열에 포함한다. 시설 수를 줄여 간격을 맞추지 않는다.
- 야영지는 세 막 모두 입구 하나의 막다른 방이다. 배경 전체에 모닥불·침구·짐을 그렸으며, 정면과 양옆은 벽이다. 기존 휴식 방식은 유지한다.
- F1 → 챕터에 모든 활성 사건의 고유 대상을 연결했다. 막 이동, 오브젝트 선택/방향/상태/배치/비우기를 사용할 수 있다.

## 아트 제작과 검수

내장 `image_gen`으로 제작했다. 최종 선택된 입력 프롬프트와 생성 원본 경로는 [GeneratedSheets.json](GeneratedSheets.json), 야영 배경은 [Camps.json](Camps.json)에 있다. 실제 설치된 캐릭터/배경을 생성 입력으로 제공했다.

스타일/카메라 기준은 `Assets/Art/World/Angular/Backdrops/B1-Walls.png`, 설치된 Warrior와 `T_Sprite_Character_절망한성직자_SeatedFront.png`다. 각 야영 배경은 해당 막의 실제 벽 배경을 편집 대상으로 사용했다. 깃발 짐승과 인형에는 실제 전투 그림도 정체성 참고로 제공했다.

최종 PNG와 방향별 파일 목록은 [ArtReady.json](ArtReady.json)에 있다. 프로젝트 저장 위치는 `Assets/Art/World/Exploration/`이며 일반 PNG로 편집할 수 있다. 상인 3방향은 기존 PNG/GUID를 유지하여 교체했다. 그림 분리는 생성 시트의 픽셀/알파를 프레임별로 분리하는 작업이며 임의의 재채색·조명 덧칠·다운샘플링은 하지 않았다.

검수 중 수정한 사항:

- 첫 상인 시안의 Warrior 투구 혼입을 반려하고 부드러운 천 후드로 다시 제작했다.
- 실제 전투가 짐승인데 빈 갑옷으로 시작하던 불일치를 찾아, 설치된 짐승을 기준으로 발견 그림과 서사를 맞췄다. 빈 갑옷 시안은 설치하지 않았다.
- 인형의 잘게 모델링된 회색 면을 반려하고 큰 면과 먹선으로 다시 제작했다.
- 오른쪽 이동 버튼이 일부 얼굴/소지품을 가리는 것을 실제 화면에서 발견하여 최초 배치 선택을 보완했다.
- 쓰러진 인형의 넓어진 자세를 발밑 폭만으로 축소하면 운반틀까지 작아지는 문제가 있었다. 별도 소진 형태의 authored `displayHeight=330`으로 실제 화면의 고정 기둥 폭/상단을 초기 그림에 맞췄다. 원본 PNG는 그대로다.
- 팝업 캡처는 화면 전환이 끝난 후 대기하여 확인했다. 초기 전환 중 캡처를 최종 표시 오류로 판단하지 않았다.

세 막의 57개 발견 화면을 [QA-B1-Subjects.jpg](QA-B1-Subjects.jpg), [QA-B2-Subjects.jpg](QA-B2-Subjects.jpg), [QA-B3-Subjects.jpg](QA-B3-Subjects.jpg)와 원본 캡처에서 비교했다. 바닥 접점, 카메라 기울기, 배경의 큰 먹선/색면, 실루엣, 버튼 가림을 확인했다. 소진 형태와 야영 방도 실제 Unity 화면에서 비교했다. [Used-Training.jpg](Used-Training.jpg)는 최종 크기 수정 후 화면이다. 접촉 그림자와 막별 조명은 기존 탐험 표시 규칙을 사용한다.

사용 중이던 Unity Editor 한 개에서 실행했다. 실제 Canvas 렌더링, EventSystem 레이캐스트와 pointer down/up/click 경로를 사용했다. 말단 선택 전부는 실제 공용 결과 적용 함수를 통해 잔존 상태를 확인했으며, 모든 분기의 경제 효과나 전투를 끝까지 플레이한 검사는 아니다. 실제 대화 선택 경로는 위 3개를 끝까지 확인했다.

처음 기존 Play를 종료할 때 `HudStructurePreparation`이 씬을 여는 기존 오류가 한 번 발생했다. Play 중에도 준비 코드가 실행되지 않도록 가드를 보완했다. 그 이후 마지막 확인까지 런타임 오류 로그 증분은 0이다. 기존 `RewardPopupView.animation` 컴파일 경고는 이번 수정 대상이 아니다.

물리 F1 키 입력이나 마우스 하드웨어를 직접 조작하는 연결 도구는 없어 그 경로는 미검증이다. 사용자 예정의 자연스러운 5회 플레이, 등장 빈도의 체감, 보상 고점/저점 및 전투 밸런스 평가는 이 확인을 대신하지 않는다. 테스트용 배치와 고정 순서는 검수 요청을 보냈을 때만 실행하며 일반 플레이 생성에는 주입하지 않는다.

마지막 상태는 MainGameScene을 연 Edit 모드다. 커밋/스테이징이나 기존 작업 초기화는 하지 않았다.
