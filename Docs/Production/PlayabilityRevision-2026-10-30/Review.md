# 플레이어 피드백 반영 · 2026-10-30

## 수정할 데이터 찾기

- Unity **Behemoth → 데이터 찾기**에서 현재 한글 이름, ID, 이전 파일명으로 검색하고 해당 에셋을 선택할 수 있다.
- 게임플레이/규칙 데이터 575개에 `Data_종류_이름` 형식을 적용했다. 몬스터는 막/역할, 공격은 소유 몬스터/공격 종류를 포함한다.
- `displayName`을 수정하고 저장하면 파일명과 오브젝트 이름도 갱신된다. GUID, ID, 기존 한국어 텍스트 키와 직렬화 참조는 유지한다.
- [DataIndex.md](DataIndex.md)는 이전/현재 경로 대조표다. 중간에 사용했던 이름도 `DataNames.json`의 별칭에 보존한다.
- 기존 편집/스테이징은 유지했다. 작업 시작 시점의 파일과 당시 미저장 메인 씬은 `Before/`에 보존했다.

## 전투·아이템·성장

- 가드 입력은 준비/차지와 진행 중 공격의 남은 타격을 취소한다. 가드 중 새 공격을 시작하지 않는다. 이미 확정된 피해를 되돌리거나 취소로 쿨타임을 초기화하지 않는다.
- 청색 매의 발톱: 일반 공격 피해 +15%, 거리 +100. 장거리 잔상: 회복 시간 -12%, 100 거리마다 피해 +6%. 이름 없는 깃발: 모든 피해 +12% 및 살아 있는 적마다 +4%로 1:1에서도 +16%.
- 붉은 계약서: 모든 피해 +25%, 받는 체력 회복 -40%. 공용 회복 규칙으로 계산한다.
- 살아남은 불씨 포션: 소지 중 사망하면 1병을 소모해 최대 HP 35%로 부활. 마시기/던지기 없이 버리기만 표시한다.
- 피로도는 시작/휴식/포션 모두 100 상한, 바로 다음 이동부터 감소해 0에 도달한다. 숨은 여유 이동은 제거했다.
- 1막 일반 무리 전투는 **레벨 4 및 일반 전투 6회**을 모두 충족해야 후보에 들어간다. 이후 무리 선택 확률은 40%. 횟수는 해당 층의 일반 전투 진입 횟수이며, 조건은 스테이지 데이터에 있다.

## 화면·몬스터

- 검 모양 공격 회복 UI를 플레이어 머리 위에 두고, 가드 수치는 왼쪽 위의 굵은 청록색 방패 게이지로 표시했다. 유지/손실/파괴 색상이 구분된다.
- 약점은 검은 외곽선, 밝은 원형 십자선, 붉은 중심점을 가진 전형적인 표적으로 변경했다.
- 몬스터의 실제 타격 시 전용 Attack 원화와 타격 궤적/충격 표시를 강조한다. 가드 성공과 비가드 피해, 강타의 표시를 구분한다. 배우의 절차적 포즈 변형은 사용하지 않는다.
- 피격 직후 붉은 화면 가장자리, HP 35% 미만에서 지속되는 위험 색조를 추가했다. 회복하면 사라진다.
- 사망 결과는 `YOU DIED`가 어둠 속에서 나타나고, 짧은 연출 뒤 복귀 버튼이 활성화된다.
- 작은 종을 해골 전사 기준으로 재조정했다. 종별 크기는 단독/무리 전투에서 같다. 큰 원화의 모든 포즈가 화면 위로 잘리지 않도록 공통 정적 배치를 계산한다.
- 겨울의 일각수, 잿불의 용, 폭풍의 대붕은 넓고 가까운 몸체로 Idle/Ready/Attack을 새로 구성했다. 대붕은 양쪽 작은 해파리 2마리를 유지한다. 기마수/수정 게/시련수/거신 등은 체적을 키우고, 백작/움직이는 갑옷처럼 단정한 인간형과 보조 우상은 콘셉트에 맞게 유지했다.
- 첫 히트박스와 해부학적 약점 위치를 저장했다. 발판은 히트박스 최하단에서 자동 계산한다. 기존 B2/B3의 HP/피해/시간/보상/약점 타격 요구량은 보존했다.

## 검증과 남은 범위

기존에 열린 Unity Editor 한 개에서 변경 범위만 실행했다. 전체 DPS/막 전체 밸런스 시뮬레이션과 별도 Unity는 실행하지 않았다.

- `Live.txt`: 가드/차지/진행 중 다단 공격 취소, 독립 접촉 3회 유지·해제·재입력, 아이템, 소지 부활, 피로도, 무리 조건, HUD/위험 상태/결과 연출 **29 PASS / 0 FAIL**.
- `Result.txt`: 실제 사망 → 전투 종료 → 제목 페이드 → 버튼 활성화 **5 PASS / 0 FAIL**.
- `NamingVerification.txt`: 임시 데이터 생성/이름 수정/참조·GUID·별칭·텍스트 키 유지/정리 **6 PASS / 0 FAIL**.
- `Visuals.txt`: 27종 크기와 실제 Sprite 영역, 보스 3종 포즈/약점/카운트다운, 무리 동일 크기, 실제 AI 일반 공격·강타와 HP 표시 **99 PASS / 0 FAIL**. `Species-Review.jpg`, `GiantRuntime-Review.jpg`, `Feedback-Review.jpg` 및 원본 캡처를 육안 검수했다. 보스 카운트다운 하단 잘림과 보조몹 이름이 몸체에서 떨어지는 문제도 수정했다.
- `DataPreservation.json`: 575개 GUID/ID/텍스트 키와 기존 전투 수치 보존 검사.
- 앞선 실행에서 발견한 빈 Sprite 영역, 상단 잘림, 결과 CanvasGroup 누락, 닫힌 인벤토리의 HP 갱신 누락을 수정했다. 이전 실패 기록은 `FirstPass/`에 남겼다.

**미검증:** 실제 모바일 기기의 두 손 터치 감각, 전체 탐험을 사람이 진행했을 때의 난도/성장 리듬, 다른 해상도/기기에서의 체감. 입력의 지속 겹침/들기/다시 누르기는 생산 입력 핸들러를 프레임 단위로 실행했으며 실제 하드웨어 터치 테스트는 별도로 필요하다.

**합의한 보류:** 비공격 유틸 주문 추가는 주문 프로토타입 작업 때 진행한다.

편집기 검색창을 처음 표시할 때 Unity 자체의 한국어 대체 글꼴 아틀라스 생성 assertion이 발생했다. 검색창에 프로젝트의 한국어 글꼴을 명시한 후에는 재발하지 않았다. 런타임 실패 기록과 분리해서 보관한다.

## 원화 검수

실제 설치된 각 종의 원화와 프로젝트 스타일 레퍼런스를 생성 입력으로 사용했다. `ArtSources.json`에 입력/프롬프트/결과를, `GiantPoses-Review.jpg`에 상태별 비교를 남겼다. 굵은 윤곽선, 큰 검정 음영, 넓고 적은 색면과 각 종의 정체성을 기준으로 검토했다. 용 Ready의 시선, 대붕 Ready의 날개 준비 자세, 일각수 Idle의 테두리 여백을 재작업했다. 설치 후 실제 전투 캡처에서 크기·약점·가림을 다시 검수했다. 배경 전체를 가로로 늘리는 방식이 아니라 새로 그린 몸체 구성을 사용한다.
