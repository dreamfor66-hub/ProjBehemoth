# 워리어 Attack · 1막 성장 밸런싱 검증

숙련 파일럿의 실제 성장 빌드 27개 전투가 모두 승리·HP 소모0으로 종료됐다. 약점을 무시하는 대조에서는 세 엘리트와 세 보스 모두 체력을 소모했다. 워리어 방어 역할 표본도 통과했다. 이는 1막 전투 프로토의 기계적 수락 결과이며 사람의 최종 난이도/실기기 손맛 승인으로 확대하지 않는다.

## 방법

기존 MainGameScene/Unity Editor 한 개에서만 순차 Play mode를 사용했다. 실제 PerkSystem 적용, 유물 장착, 경험치 문턱, 피로 곡선, 공격 쿨타임, 차지 준비시간, 영창·MP·주문 쿨타임을 사용했다. 정규화 공격력/HP 보너스를 주입하지 않았다. 파일럿은 적 공격 직전0.2초 가드, 인바운드 부위 약점 베기와 일반 공격/주문을 수행한다. 2배속은 자동 측정용이며 아래 시간은 게임 시간이다. 시간 측정 중 캡처를 꺼 프레임 정지로 가드 창을 놓치는 계측 간섭을 제거했다.

각 전투는 선언한 성장과 초기 HP로 시작한다. 사람의 실제 입력·학습 난이도나 연속 무작위 런의 완주율 측정이 아니다. 모바일 양손/큰 제스처 체감과 전체 클래스 DPS 비교는 이번에 수행하지 않았다.

## 워리어 방어 역할

Matched middle progression: XP115, two actual perks/shared chest relic, each class's own starter. Six identical 19.2 damage/19.2 shield attacks every 2.657s. Existing runtime guard/regen/damage, not offense or class DPS comparison.  
Warrior HP hits=1, HP lost=19.20  
Rogue HP hits=3, HP lost=57.60  
PASS Warrior has a bounded defense advantage.  

가드 유지·회복이라는 방어 축만 비교했다. 각 클래스의 공격/약점 효율을 재밸런스한 결과로 주장하지 않는다.

## 성장·피로의 결과

기준/성장 부족/피로60/추가 성장 순으로 스핑크스59.94/75.34/92.07/44.00초, 종36.43/42.80/52.46/28.51초, 공작부인35.98/41.58/50.27/27.78초. 기준보다 성장 부족은 약16~26%, 피로 누적은40~54% 길고, 추가 성장은22~27% 짧다. 부족/피로 조건에서도 정확한 가드·약점으로 무피격은 가능하지만 공격 노출과 공략 횟수가 늘어난다.

## 적용·보존 확인

- 실제 보상53개 환산, 고정 빌드8개. 누적XP373.53→4회 레벨업, 요구4.55U, 방문/구매/이벤트 수락 가정을 명시한 공급6.046U. GrowthBalance.md와 GrowthSpecification.json에 개별 근거/경로 보존.
- 시작 유물 초당2 회복이 전투 시작에 사라지던 정의를 고치고, 붕괴 보너스는3으로 보정. 사냥꾼의 등불 처치회복7과 번개 심줄 일반피해/쿨타임이 실제 적용되는 불변식 통과.
- 실제 일반전 추첨에서 제외됐던 3인 흡혈박쥐·거미 편성을 2인으로 수정. 개체 크기를 줄이지 않음.
- 워리어 기본 무기피해·공격 주기와 B2/B3 몬스터 수치는 유지. 후속 막 요구12/20U는 이전 미검증 초안.
- 원화는 최종 Attack만 교체, 기존 Ready/Idle/.meta 보존. 사진·GIF 레퍼런스와 육안 비교는 References/References.md와 Art/Review.md.
- 기존 Editor 한 개에서 모든 suite를 순차 실행하고 종료했다. 이미지 반복마다 시스템 검증을 추가하지 않았다.

## 이력과 계측 오류

첫 매트릭스의 종/방어 빌드 스핑크스 피해는 시작 유물의 회복이 전투 시작 때 사라지는 정의 문제를 드러냈다. 두 번째 매트릭스의 고블린10.8HP는 전투2초 시점 캡처 정지로 가드 창을 놓친 계측 간섭이었다. FinalTight는 캡처 없이 고블린0HP를 재확인했고 최종27전 모두0HP다. 첫 두 결과를 최종 통과 수치로 재분류하지 않고 원자료로 남겼다.

재개 예약 id1은 두 결과의 수락 근거 저장 후 PAUSED로 비활성화했다. 사용량 초기화권/크레딧은 소비하지 않았다. 마지막 변경은 기존 성장 초안의 자동 덮어쓰기를 막는 Editor 보호이며 Unity 재컴파일을 확인했다.
