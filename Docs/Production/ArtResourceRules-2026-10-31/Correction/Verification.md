# 미사용 리소스 정정

첫 정리에서 프레젠테이션 데이터 자체를 모두 사용 루트로 인정한 판단이 잘못됐다. 스크린샷의 거미·겨울의 일각수 등 `Assets/Art/Enemies/Combat` 그림은 고아 애니메이션 데이터에만 연결돼 있었다.

- 저장된 씬·프리팹·게임플레이 데이터에서 프레젠테이션 데이터의 실제 사용을 추적하도록 기준을 수정했다. 코드의 자동 제작 경로와 완료 표식도 확인했다.
- 구형 미사용 프레젠테이션 에셋 **164개**와 종속 아트 **204개**를 추가로 삭제했다. 구형 CombatSpriteAnimation 84개, Sprite 51개, 미사용 공격 데이터 27개, 얼굴/표시 설정 각 1개가 포함된다. 정확한 삭제 경로는 DeletionAudit.md에 있다.
- MonsterView 프리팹의 오래된 미리보기 Sprite 참조 2개는 현재 해골 전사 Idle 그림으로 교체했다. 실제로 사용 중인 훈련 인형 원화 4장은 GUID를 보존해 `Assets/Art/Monsters/경량훈련인형`으로 옮겼다.
- `Assets/Art/Enemies/Combat` 전체와 그 .meta, 거미·겨울의 일각수 하위 폴더는 삭제됐다. 별도의 미사용 원본 폴더에 옮겨 남기지 않았다.
- 유지한 에셋 **1,820개**의 GUID·직접 의존성·Sprite 파일 ID·텍스처·크롭·피벗·PPU를 확인했다. 직렬화 파일 **2,898개**를 독립 스캔해 삭제 GUID 참조 **0개**를 확인했다. Audit.json에 결과가 있다.
- 삭제 완료 후 기존 Unity Editor에서 다시 실행해 **54 PASS / 0 FAIL**을 확인했다. 몬스터 44종과 캐릭터 6종의 이미지 연결, UI 아이콘 160개, 실제 몽크 공격·일각수 준비 그림·HUD 얼굴·가방 표시가 통과했다. Live.txt와 LiveComplete.txt에 결과를 보존했고 Play 모드를 종료했다.
- 아트 규칙에 ‘고아 프레젠테이션 데이터가 구형 아트를 사용 중으로 만들지는 않는다’는 기준을 추가했다. 과거 prepare.py의 잘못된 정리 경로는 중단하고 Correction/prepare.py를 사용한다.

Unity에서 폴더 생성과 일괄 이동을 같은 임포트 중지 구간에서 처리해 첫 이동이 거절된 오류는, 폴더 임포트를 먼저 완료하도록 수정했다. 실패 시 아트 삭제는 시작되지 않았으며 재실행과 전체 참조 비교가 통과했다. 해당 진단은 ResolvedFolderImportError.txt에 보존했다.
